# Component reports

One report per phase/component after implementation; it also serves as the PR description.

Template:

```markdown
# NN. <Component> — report
## What was done (3–5 points in plain language)
## Mapping to decisions
| Decision | Where in the code | How it was verified | Status |
## Deviations from the specification and why
## Live example (input → output)
## Test results (numbers against the acceptance criteria)
## How to check it yourself (2–3 commands)
## What you should look at (checklist)
## Risks, open questions, what is needed next
```
